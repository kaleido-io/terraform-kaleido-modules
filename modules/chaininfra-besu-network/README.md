# chaininfra-besu-network

Deploys a Besu network (`kaleido_platform_network`, type `Besu`) and the
`chain_infrastructure` stack that wraps it. Besu nodes attach to the network via
the stack and network IDs this module outputs.

By default the network initializes in `automated` mode, bootstrapping a genesis
from strongly-typed `bootstrapOptions` (QBFT consensus, EIP fork config with
Shanghai and Osaka active at genesis, block-config flags, and optional initial
validators/balances).

## Usage

```hcl
module "besu_network" {
  source = "git@github.com:kaleido-io/terraform-kaleido-modules.git//modules/chaininfra-besu-network?ref=main"

  environment_id = kaleido_platform_environment.env.id
  network_name   = "besu"
  stack_name     = "besu"

  initial_balances = {
    "0x12F62772C4652280d06E64CfBC9033d409559aD4" = "0x111111111111"
  }
}
```

### Bring-your-own genesis

Render the genesis in HCL and supply it inline. The network switches to `manual`
init mode and consumes the file verbatim as the `init` file set, so you own and
upgrade the genesis over time:

```hcl
module "besu_network" {
  source = "../../modules/chaininfra-besu-network"

  environment_id = kaleido_platform_environment.env.id
  genesis_json = jsonencode({
    config = { chainId = 12345, shanghaiTime = 0, qbft = { blockperiodseconds = 5 } }
    # ...
  })
}
```

## Outputs

- `network_id` — pass to the chaininfra-besu-node module's `network_id`
- `stack_id` — pass to the chaininfra-besu-node module's `stack_id`
- `network_name`
- `chain_id` — generated by the platform in automated mode when `chain_id` is unset
- `network_info` — full top-level config captured after creation
